# FlowLab

**Flowchart** editor and runner that works entirely in the browser.
It is a single HTML file: it opens in Chrome with a double click and also works offline.
It reads and saves programs in the **`.fprg`** (XML) format used by the flowchart editors most common in schools.
The interface is multilingual (English and Italian, and any language added as a JSON file).

The software was created with **Claude Opus 5.5** by Anthropic.

👉 **To use it:**
- **online**, without installing anything: open <https://nicvac.github.io/flowlab/dist/FlowLab.html>;
- **as an app**: from the online version, File menu › *Install FlowLab as an app* (Chrome or Edge); it opens in its own window and also works without a network;
- **offline**: download [`dist/FlowLab.html`](dist/FlowLab.html) and open it with Chrome.

### Opening a program from a web address

Adding `?url=` followed by the address of a `.fprg` file, FlowLab opens that program directly:

```
https://nicvac.github.io/flowlab/dist/FlowLab.html?url=https://github.com/user/repo/blob/main/exercise.fprg
```

- Files on GitHub (also the «blob» link of the file page: FlowLab turns it into the raw file), in Gists and on GitHub Pages work. Other sites work if they allow reading from other pages (CORS).
- After opening, the parameter disappears from the address bar: reloading the page you find your own work again. The program that was open before is recovered with Ctrl+Z.
- From the File menu: *Open from web address…* and *Copy the link to this program*, to share it with the class.
- The [`examples/`](examples/) folder contains all the examples in `.fprg` format, with links that open them directly in FlowLab.

## Features

- **Editor:** click an arrow to add a block, double-click to edit it, drag to move it; several blocks are selected with Shift+click (from the selected one to the clicked one, also Shift+↑/↓), Ctrl+click (one more or one less), a rectangle drawn with the mouse on the empty sheet (with Shift or Ctrl it adds) or Ctrl+A, and copied, cut, pasted, duplicated, deleted or moved together; undo/redo, several functions with parameters and arrays.
- **Blocks:** Declare (with an optional initial value, shown with the arrow of the assignment: `a, b: Integer ← 0`), Constant, Assign, Input, Output, Call, If, While, For, Do-while, Comment, Breakpoint, File (Open, Read, Write, Close). If the text of a block does not fit in the box, the + button shows all of it on several lines.
- **Execution:** four speeds, step-by-step execution (Step enters the called functions, Step over runs them without entering, Step out runs the rest of the current function and stops after the call) with the current block highlighted and a cursor that follows the arrows taken (branches of the Ifs and returns of the loops included), breakpoints, error messages in the chosen language with the block in error marked in red. While the program runs or is paused, with a right click on a block: **Run to here** (runs without animation up to that block, e.g. to leave a loop) and breakpoints marked on the block (also F9, at any time), also with a condition (`i = 5`): a red dot, only for the session, not saved in the file.
- **Compact view** (*Compact* button at the top left of the diagram, Shift+K): simple blocks in sequence (declarations and constants, assignments, input, output, calls, comments, breakpoints) touch each other, without arrows between them, and keep their width; the diagram becomes shorter. A newly opened diagram is always in the extended view, and exports (SVG, PNG, PDF) always use the extended view. In both views, below the body of a loop the return arrow starts at once and, if the body ends with another loop, its exit goes straight into the return, without steps; after an If the line goes down a little from its junction before turning, so it does not run along the branches.
- **Moving the sheet (pan)**: hold **Space** and drag, or drag with the middle mouse button (double click with it: back to the start), or turn on the hand (button next to the zoom, or H; Esc turns it off) and drag; with nothing selected the arrows move the sheet. Around the drawing there is empty paper, so also a small diagram (or the class diagram) can be placed anywhere; each view remembers where it was on each diagram, *Fit* (Shift+1) brings the drawing back to the start, and Ctrl+wheel zooms around the cursor. Dragging a class against the edge of the view scrolls the sheet. A *Continue* view is linked to the main sheet only vertically: it starts with the drawing in its middle, then it is moved horizontally by itself, while dragging it or turning the wheel on it vertically scrolls the main sheet.
- **Auxiliary views** (*New view* button next to the zoom, Ctrl+Alt+V): floating, resizable windows, as many as you like, each with a diagram of the program (also the same one as the main sheet, on another part, or the class diagram). As in the main sheet, *Compact* is at the top left of the view and the zoom at the bottom left; a view can also cover the side panel. In the views you navigate and edit as in the sheet: commands and keys act on the view you clicked, and a block can be dragged from one view to another. With **Continue** the view shows the part of the diagram the main sheet does not show and scrolls with it (also with the wheel on the view): if the sheet is scrolled down, the part cut off at the top; otherwise the rest, the part beyond the bottom. With several *Continue* views, the first shows the top part (if cut off) and the others, in a row, the rest; a coloured, numbered dashed line marks the point in common. When at least one whole block is cut off at the top (the sheet is scrolled down) and no view shows it, a red dot appears on the *New view* button (not for the part beyond the bottom, which is reached by scrolling): pressing it, the new view opens already in *Continue* mode. During execution blocks light up in all the views that show them (the animated cursor stays in the main sheet). Views are remembered with the open program and closed when another one is opened.
- **Panels:** input/output console, variables (just-changed ones in yellow, with the call stack), virtual text files. When a program starts (new, opened from a file or a web address, an example) the side panel shows the Code tab, in the language last chosen (Java the first time). Tabs are reordered by dragging and can be detached into floating windows to place anywhere, collapsible to the title bar; the side panel hides and reopens with the small button on the divider (Ctrl+B). In a narrow window the panel goes below the diagram with the same divider: drag it to change its height, the button hides and shows it. The layout is remembered.
- **Multi-dimensional arrays**: `m[3, 4]` is declared by giving the dimensions separated by commas and used with `m[i, j]` or `m[i][j]`; `Size(m, d)` gives the number of elements of dimension `d`. An array can also be declared with its initial values between braces, written in the field of the number of elements (they give the size too): `v[]: Integer ← {3, 1, 2}`, `m[]: Integer ← { {1, 2, 3}, {4, 5, 6} }` (one pair of braces per row, all rows of the same length); in the code they become the initializers of each language (`{…}` in Java, C# and C++, `[…]` in Python and JavaScript), and in the standard `.fprg` format an assignment for each element.
- **Array viewer for debugging**: from the Variables tab every array opens in a floating window. A one-dimensional array is a strip, a two-dimensional one a chessboard, a three-dimensional one a cube opened like a book (you leaf through the first dimension, each page is a chessboard on squared paper); beyond three dimensions the first ones are chosen with index selectors. Only the cells that fit in the window are shown, fading where there are more, and during execution the view moves to the cell just changed.
- **Constants**: a dedicated block (`MAX: Integer ← 100`) with a value that cannot be changed; in the code they become `const` (C++, C#, JavaScript), `final` (Java) or an uppercase variable (Python).
- **Functions with several return values**, as in Python: `min, max, idxMin, idxMax ← computeMaxAndMin(V, N)`. In the generated code they become tuples in Python and C#, `std::tie` in C++, a `record` in Java (16+), a destructured array in JavaScript. It is a FlowLab extension: other programs that use the `.fprg` format cannot run these programs.
- **Exceptions**, in the Functions view and in the Objects view, with the terms of Java:
  - the **Try** block protects the blocks it contains; on the right the dashed line leads to the **Catch** branches, one per exception type (checked in order, more specific types first), which join below; the optional **Finally** always runs and is drawn in a dashed frame, so it is clear where it ends;
  - the **Throw** block throws an exception: `Throw new Exception("invalid grade")`; in a Catch, `Throw e` rethrows it;
  - predefined types, with the same English names in every language: `Exception` and its subclasses `DivisionByZero`, `IndexOutOfRange`, `InvalidArgument` (a value not allowed for a parameter) with its subclass `InvalidConversion` (ToInteger, ToReal), as in Java, `NullReference`, `FileError`, `EmptyStack` and `NoSuchElement` (used by the Stack and Queue modules). Interpreter errors of these types become exceptions that can be caught. In the Objects view you create your own exceptions with *New exception…* (class diagram menu, Shift+E): they inherit from a predefined exception or from another exception of the program and can have attributes and methods. Classes and exceptions stay separate: a class inherits only from classes, an exception only from exceptions. In the class diagram exceptions have their own colour, and the predefined exceptions the program inherits from appear by themselves, dashed and read-only, with the `message` attribute and the constructors to call with `super(message)`; when the diagram opens they place themselves in the best spot, usually above the subclasses, and then they can be moved by dragging (the position is not saved in the file);
  - in the Catch `e.message` is the message of the exception; the exception goes up from the called functions to the first Try that catches it. If nobody catches it the program stops with the type, the message and the chain of calls. During animated or step-by-step execution, when an exception starts the block it comes from is circled in red, a label shows its type (and the function it comes from, if it comes from a call) and the cursor follows a dashed red arrow to the Catch that catches it, or to the Finally, after which the exception continues;
  - in the code: `try`/`catch`/`finally` in Java (checked exceptions: FlowLab writes the necessary `throws` in the signatures), C# and JavaScript (a single `catch` with `instanceof`), `try`/`except`/`finally` in Python, `try`/`catch` in C++ (the Finally is obtained by catching everything and rethrowing). The predefined types become those of the language (`ArithmeticException`, `ZeroDivisionError`, `out_of_range`…); where the language throws nothing (division between reals by zero, an index outside the array in Python, JavaScript and C++, a conversion like `stoi("12a")`) the code uses small check functions, only if the program catches that type of exception.
- **Arrays as return values**, like the parameters: in the function dialog every return value has its shape (value, array, matrix…). The call is assigned to an array, `v ← squares(10)`, and `v` becomes the returned array (as in Java); with several values `grades, n ← readGrades()`. A method can also return an array attribute of its class. In the code: `int[] squares(int n)` in Java, `int[,]` in C#, `vector<int>` in C++ (where the returned array is copied).
- **Classes and objects (Objects view)**: the *Functions / Objects* command in the bar changes view. In the Objects view the sheet shows a **UML class diagram**: each class has attributes and methods with the access modifiers (`+` public, `-` private, `#` protected), static members are underlined, arrows show inheritance and associations (attributes whose type is another class, with the multiplicity). At first the program is a single class with the functions as static methods; the Functions view stays available as long as there is a single class with only static, public methods.
  - Double-click a method: its flowchart opens, drawn like a function. Right-click a class: new attributes, methods and constructors. Classes are moved by dragging them; an attribute or a method dragged onto another class moves into it, or to another place of the same class (not the constructors, which belong to their class, and not the Main). The code that uses the member does not change: FlowLab warns when a class already has a member with that name, when an abstract method would go into a class that is not abstract, and when the member uses a Generic Type the other class does not have.
  - **Autocompletion:** typing the dot after an object (`p.`, `this.`, `list.get(0).`) or after the name of a class (`Point.`) shows the list of the methods and attributes that can be used there, with their types (for an `ArrayList<Integer>` you see `add(x: Integer)`), the inherited ones and respecting private and protected; choose with the arrows and Enter or Tab.
  - In expressions: `p ← new Point(1, 2)`, `p.x`, `p.move(3, 4)`, `this.x`, `Point.counter`, `super(...)` as the first block of a constructor, `super.method()`, `null`.
  - Inheritance with method overriding (polymorphism), several constructors with different parameters, static attributes and methods, initial values of attributes.
  - **Abstract classes and methods**: an abstract class («abstract», name in italics) creates no objects; an abstract method has no body and the subclasses define it (opening it shows their versions). FlowLab points out concrete subclasses that do not define an inherited abstract method. In the code: `abstract` in Java and C#, `= 0` in C++, `ABC` and `@abstractmethod` in Python. Access modifiers are checked during execution: reading a private attribute from outside the class gives an error, as in Java.
  - In the Variables tab objects open with the small arrow to show their attributes; `this` and the static attributes appear too.
  - A click on the value of a reference (`Node#1`) opens the object in a window, linked to the row it was opened from. If during execution that row moves to another object (for example `head` from `Node#1` to `Node#2`), the new object opens too in place of the old one, which moves down and stays open, linked to another row that still points to it (`Node#2.next`): step by step you see the chain of references grow.
  - In the generated code they become real classes: `extends`/`super` in Java, `: base(...)` and `virtual`/`override` in C#, pointers, `virtual` and initializer lists in C++, `self` and `super().__init__` in Python, `class`/`extends` in JavaScript. In Python and JavaScript, which have no overloading, the versions with different parameters are gathered in a single method that chooses according to the arguments.
- **Generic Types** (`T`, `S`, `V`…): in the type menu of a parameter or an attribute there is the item *New Generic Type*. Choosing it, FlowLab assigns a free name (first `T`, then `S`, `V`…) and from then on the same Generic Type can be reused in the other menus («T (Generic Type)»), also inside another type (`Pair<T>`). There is nothing to declare first: the Generic Type appears where it is used and disappears when nobody uses it any more.
  - **In classes**: a Generic Type used in an attribute, in a constructor or in a non-static method belongs to the class, which becomes `ArrayList<T>`, `Pair<T, S>`. Variables are declared `ArrayList<Integer>` and objects are created with `new ArrayList<Integer>()` or `new ArrayList<>()` (the type is inferred from the variable); the interpreter checks the types of the elements. A class already used in the program cannot gain or lose Generic Types. A class can inherit from a class with Generic Types by choosing their types next to the parent class: `Pila<T> extends Lista<T>` (the subclass passes on its own Generic Type), `ListaInteri extends Lista<Integer>` (a fixed type), `Coppia<K, V> extends Lista<V>`; the inherited attributes and methods take those types (in `ListaInteri`, `get(i)` returns an `Integer` and `add(x: Integer)` overrides `add(x: T)`), an object of the subclass can go in a variable of the parent class (`Lista<Integer> q ← new Pila<Integer>()`), the class diagram writes the types on the inheritance arrow («bind» T→Integer), and when the parent class gains or loses a Generic Type its subclasses follow. In the code: `class Pila<T> extends Lista<T>`, `class Pila(Lista)`, `template <typename T> class Pila : public Lista<T>` (with `this->` for the inherited members), `class Pila<T> : Lista<T>`. Two arrays can be assigned (`a ← b`): `a` becomes the same array as `b`, as in Java.
  - **In functions and static methods**: the Generic Type belongs to the function (`maximum<T>(v: T[], n: Integer): T`). At each call `T` is inferred from the arguments: `maximum(grades, 5)` with an array of Integers, `maximum(names, 3)` with one of Strings; if the arguments give `T` two different types (an Integer and a Real) the interpreter reports it. For this reason a new Generic Type is created in the parameters; in return values and declarations the existing ones are used.
  - Values of a Generic Type are compared with `= != < <= > >=`.
  - In the code: `class Pair<T>` and `static <T> T maximum(T[] v, int n)` in Java, with comparisons written as methods of the object, as for Strings (`a.equals(b)`, `a.compareTo(b) < 0`), and with `T extends Comparable<T>` only if the `< >` comparisons are needed; arrays of base types passed to a function with a Generic Type become `Integer[]`, `Double[]`. In C# `class Pair<T>` and `maximum<T>(...)` with `where T : IComparable<T>`; in C++ `template <typename T>`.
- **Modules** (*Import module* button next to *Examples*, or Ctrl+I): a module is a normal `.fprg` program to reuse. Modules come from **collections on GitHub**: a collection is a folder of a public repository in which each subfolder is a topic (`data_structures` becomes «Data structures») and contains the `.fprg` files. In the dialog collections are browsed as a tree (collection › topic › modules) and a collection is downloaded from GitHub only when it is opened. By default there is the [official collection](modules/) (data structures: `ArrayList<T>`, `Stack<T>`, `Queue<T>` with the Java constructors, including those with the initial capacity and those that copy another structure, and the exceptions of Java: a position outside the list throws `IndexOutOfRange`, a negative capacity `InvalidArgument`, `pop`/`peek` on an empty stack `EmptyStack`, `remove`/`peek` on an empty queue `NoSuchElement`; sorting and searching algorithms; `Strings`, functions on strings like the methods of `String` in Java: `Substring`, `IndexOf`, `Contains`, `StartsWith`, `EndsWith`, `ToUpper`, `ToLower`, `Trim`, `Replace`, `Split`, `IsDigit`, `IsLetter`); others can be added by pasting the link of the folder, and a module can also be imported from a file or from a web address. The description shown is the one written in Program properties. If the module has classes, the classes appear in a «module …» box of the class diagram, which can be collapsed (only the class names) or expanded with the small button on the box, with *Collapse modules* or with Shift+M; if it has only functions, the functions are added to the program and called by name, without changing view. In the Objects view these functions belong to no class: the class diagram shows the module as a box of its own with the functions (double-click one to open its flowchart), and they can be called by name from every class; in the generated code they become static methods of a class with the name of the module (`Sorting.bubbleSort(v, n)`), except those that the language already has. In the menu of the diagrams the functions and classes of the program come first, then one group for each imported module, collapsed: the + button (or the right arrow) shows what was imported from it. In both cases they stay read-only (their flowcharts can be opened and followed step by step), they are updated and removed from the same dialog, and the Main of the module is only for testing it. Anyone can write a module, even a student. In the generated code the modules of the official collection that have an equivalent in the language use the classes already available (`java.util.ArrayList`, `Stack`, `Queue`; `list` and `deque` in Python; `vector`, `stack`, `queue` in C++; `List`, `Stack`, `Queue` in C#; arrays in JavaScript), and the functions of `Strings` become those of each language (`s.substring(a, b)` and `s.split(…)` in Java, `s[a:b]` and `s.split(…)` in Python, `s.substr(…)` in C++, `s.Substring(…)` in C#, `s.substring(a, b)` in JavaScript), with a small helper function only where the language has none; the others become classes or functions written in the code.
- **Stage**: an animated scene that follows the variables of the program while it runs, in a floating window. The stage says which variables it needs (an array of integers for a row of penguins, an integer for a counter…) and the program binds each one to one of its variables; when a bound variable changes the scene animates the change (a value set, two values exchanged, an element inserted or removed in an `ArrayList`, `Stack` or `Queue` of the modules) and **the program waits for the end of the animation**, at any speed (the block that made the change stays lit meanwhile). A stage is a `.flstage` file, a JavaScript module that can use libraries from a CDN (e.g. GSAP); it has its texts in several languages and speaks the language of FlowLab (the stages of the examples in Italian and English). A program links 0 or more stages (*File › Stage*): the `.fprg` saves their names (the stage files stay **in the same folder** as the program) or web addresses, the bound variables, the active stage and whether its window is collapsed. In the title bar of the window: the active stage (one at a time), the speed of the animations, the bindings, the download of the stage, the unlinking, and the collapse to the title bar, which **unloads** the stage. A program opened from a web address finds its stages next to it; from the computer, open the program together with its stage files (or choose them when the window asks). The code of a stage runs isolated from the page (sandboxed iframe); without stages the code of the stages is not even loaded, and with the window collapsed the stage is unloaded: in both cases the execution is exactly as before. In the list of the examples an icon marks those linked to stages. The examples come linked to their stages: bubble sort (penguins on an ice field that push piles of ice blocks and change places), guess the number (snowballs thrown on a row of ice slabs, and a sports car on the seaside road of a neon city at sunset), Euclid's GCD (sticks of light, and bars of ice blocks) and the recursive factorial (a tower of blocks, and a tower of ice); the format is described in [docs/stage.md](docs/stage.md), written so that new stages can be generated with an AI.
- **Installation as an app** (File menu › *Install FlowLab as an app*, or the install icon in the address bar of Chrome or Edge): from the [online version](https://nicvac.github.io/flowlab/dist/FlowLab.html) FlowLab is installed on the computer or Chromebook and opens in its own window, with the icon among the apps; it also works without a network (the page is asked to the network first, so there is always the latest version, otherwise the saved copy is used). Once installed, FlowLab opens `.fprg` files with a double click or with «Open with» (each in its own window) and Ctrl+S saves them right there. A copy downloaded locally cannot be installed: the menu item explains where to do it. Chrome does not install apps in guest mode: there FlowLab works in a tab (save the `.fprg` before closing).
- **Languages** (File menu › *Language*): the interface, the diagrams (Main/End, True/False, the types Integer, Real…), the messages of the execution, the keyboard shortcuts of the blocks, the pseudocode and the comments of the generated code are in the chosen language; the examples have their own version in each language. The first time FlowLab uses the first browser language it has, otherwise English, and then it remembers the choice. Some things have a single name in every language, in English: the predefined exceptions with the `message` attribute, the built-in functions, the keywords of the expressions. `.fprg` files are the same in every language. See [Adding a language](#adding-a-language).
- **Generated code:** pseudocode (in the chosen language), Python, C++, Java, C#, JavaScript; the size of the text is set with A− A+ (or Ctrl + wheel on the code) and remembered. Code and flowchart are linked: a click on a block highlights its lines in the Code tab (all of them, e.g. the header and the closing of a loop), a click on a line highlights the blocks it comes from (two, when a declaration and its assignment become one line; the sheet goes to that function), and during execution the line of the running block lights up with it.
- **Export:** `.fprg`, SVG, PNG, source code and **the whole project as PDF** (cover with contents, class diagram, flowchart of each function or method with the texts expanded, each one whole on a page as tall as needed, meant for on-screen reading, with the text of the blocks always at 9 pt (diagrams wider than an A4 widen the page); source code in the language chosen in the Code tab, on landscape A4 pages and coloured as in the tab).
- **Keyboard shortcuts** for all operations, shown in the context menus, in the button tooltips and in the Quick guide (F1). A letter adds a block after the selected one (in English: D Declare, A Assign, I Input, O Output, F If, W While, R For, L Do-while…; the letters come from the language file; also in the «Add a block» menu), Alt+↑/↓ moves the block; in the class diagram A, M and C add an attribute, method and constructor to the selected class, N a new class; F2 edits, PgUp/PgDn move from one diagram to another.
- **Ready-made examples:** grade average, even/odd, times table, Euclid's GCD, guess the number, recursive factorial, bubble sort, minimum and maximum, matrices and cubes, bank account, geometric shapes, animals (abstract classes), linked list, reading/writing files, exceptions (Try, Catch, Finally, Throw), account withdrawals (user exceptions).

## Compatibility with the .fprg format

FlowLab is compatible with the **standard `.fprg` format**.

- **Opening:** standard `.fprg` files open in FlowLab. Turtle graphics blocks are not supported and are dropped with a warning.
- **Saving:** if the program does not use the extended features, FlowLab saves in the standard `.fprg` format and the file opens in the other editors that use this format.
- As the format requires, the names of variables and functions are case-insensitive. Strings written between single quotes are saved between double quotes.

### Extended .fprg format

If the program uses one of the extended features of FlowLab, the file is saved in an **extended, non-standard `.fprg` format**. The extended features are:

- constants
- multi-dimensional arrays
- functions with several return values
- functions returning arrays
- exceptions (Try, Catch, Finally, Throw)
- classes and objects
- classes and functions with Generic Types
- imported modules
- declarations with an initial value
- the `xor` operator
- the functions `Min`, `Max`, `Pow`, `Round`, `Floor`, `Ceil`
- escape sequences in strings (`\n`, `\t`, …) and strings on several lines

### Verification

`node test/compat.mjs <folder with .fprg files>` opens each file, checks blocks, expressions and names, saves and reopens, verifies that the saved file uses only the standard format and runs the program.

## Expression language

| Operators | Meaning |
|---|---|
| `+ - * /` | arithmetic (`/` always gives a real) |
| `mod` `%` | remainder |
| `^` | power |
| `&` | concatenation of texts and numbers |
| `=` `==` `!=` `<>` `<` `<=` `>` `>=` | comparisons |
| `and` `&&` `or` `\|\|` `not` `!` | logical |
| `xor` `⊕` | exclusive or: between Booleans true when exactly one of the two is true, between Integers bit by bit (`(6 xor 3) = 5`); in precedence between `or` and `and` |

Built-in functions: `Abs, Arccos, Arcsin, Arctan, Cos, Sin, Tan, Cosh, Sinh, Tanh, Int, Ln, Log, Log10, Sgn, Sqrt, Random, Len, Char, ToChar, ToCode, ToFixed, ToInteger, ToReal, ToString, Size, EOF`, constant `Pi`.

Extended numeric functions: `Min(a, b, …)` and `Max(a, b, …)` with 2 or more arguments, `Pow(b, e)` (as `b ^ e`), `Round(x)` (halves up: `Round(2.5) = 3`, `Round(-2.5) = -2`), `Floor(x)`, `Ceil(x)`; the result is Integer when the arguments are Integer (Round, Floor and Ceil always give an Integer). A function of the program with the same name (written before these functions existed) still wins.

Escape sequences in strings: `\n` new line, `\t` tab, `\r` carriage return, `\\` backslash, `\"` and `\'` quotes; any other backslash stays as it is. They are shown in red in the fields, in the diagram and in the code. In the *Output* dialog, **Enter inside a string** goes to a new line and the string contains the line break (outside a string Enter confirms the dialog); in the diagram the block shows the text on several lines, in the code the line break becomes `\n`.

## Adding a language

The languages are JSON files in [`languages/`](languages/), one per language (`en.json`, `it.json`). FlowLab includes those of the repository in the page (they work offline) and, in File › Language, also lists those found in the folder on GitHub: a new file there appears in the menu without a new version of FlowLab.

A language file has these sections:

| Section | Content |
|---|---|
| `language`, `name` | code (`fr`) and name of the language in the language itself (`Français`) |
| `strings` | the texts of the interface, diagrams and messages, by id: `"ui.newClass": "New class"`; values in braces (`{name}`) are filled in by FlowLab |
| `keys` | names of the keys in the texts built by FlowLab (`"Shift": "Maiusc"`) |
| `shortcuts` | the letter that adds each kind of block (`"while": "W"`, `"read": "Shift+R"`) |
| `code` | texts of the generated code: comments, messages and the words of the pseudocode |

To start a new language, copy `en.json`, change `language` and `name` and translate the values. Missing texts are shown in English. `node tools/i18n_check.js` lists the missing texts of each language and checks the placeholders and the shortcuts. The examples of a language go in `examples/<code>/` (see [`examples/`](examples/)); without that folder FlowLab shows the English examples.

In the code every text is written as `L('ui.newClass')` or `L('run.varHasNoValue', { name })`, with the text in `languages/en.json` and the other languages.

## Structure

```
src/
  i18n.js      languages: texts by id, language choice, files from the languages folder
  expr.js      lexer, parser, typed values, built-in functions, evaluator
  model.js     program model, reading/writing .fprg
  interp.js    generator-based interpreter (step by step, input, breakpoints)
  codegen.js   code generators (pseudocode, Python, C++, Java, C#, JS)
  render.js    layout and SVG drawing of the diagram
  uml.js       class diagram
  pdf.js       writing PDF files
  arrayview.js windows to view arrays and objects
  examples.js  example programs (from the examples folder)
  app.js       interface
  style.css, body.html
  pwa/         installation as an app: service worker and icons (regenerated with node tools/icons.mjs)
languages/     one JSON file per language (build.py includes them in the page)
examples/      the examples in .fprg format, one folder per language (README regenerated with node tools/examples.js)
modules/       module library by topic (regenerated with node tools/modules.js; build.py includes it in the page)
build.py       joins the sources into dist/FlowLab.html (standalone) and dist/artifact.html; also writes manifest, service worker and icons for the installation as an app
tools/         examples README, module library, icons, language check
test/          Node and Playwright tests
```

To rebuild: `python3 build.py`.
Tests: `node test/node_interp.js`, `node test/node_oo.js`, `node test/node_codegen_oo.js run` (compiles and runs the generated object-oriented code and compares it with the interpreter), `node tools/i18n_check.js`, `node test/ui.mjs`, `node test/oo_ui.mjs` and `node test/lang_ui.mjs` (they require Playwright).
